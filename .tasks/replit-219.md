# CPU исполнение без графического ускорения

## Что и зачем
Обеспечить функционально полный путь при отсутствии/отказе GPU без возврата растровой модели карты и без дублирования игровых правил.

## Готово, когда
С тем же контурным источником работают заливки, границы, подписи, иконки и высоты; отсутствие аппаратного ускорения не теряет данные и не блокирует интерфейс.

## Точный алгоритм участка
Использовать общие подготовленные полосы/пути/треугольники; математические задачи исполнять CPU/WASM-пулом по существующему контракту. Для 2D повторно использовать подготовленные векторные пути, изменять матрицу и материал, не создавать изображение карты и не применять drawImage для её кэширования. Возможность ускорения конкретного API не выдавать за CPU-замер: режим теста должен принудительно отключать соответствующее ускорение и сообщать реальный backend.
Для 3D использовать тот же mesh, матрицы и правила глубины через программный исполнитель; экранный буфер является только результатом вывода, не источником карты и не масштабируемым снимком. Отсечь невидимые грани и сохранять подготовленные данные; тяжёлые вычисления вынести из UI. Резервный путь включается через общий интерфейс возможностей и не содержит отдельных правил географии/цвета/видимости.

## Проверки и пороги
Отдельно принудительно отключить GPU для каждой математической операции и сценария вывода, сравнить геометрию, результат цвета и видимость. S: CPU-кадры p95≤33,4 мс, ввод≤50 мс p95, UI-работа≤4 мс p95; новые контуры готовятся вне UI. Проверить отсутствие GPU, отказ выделения и потерю контекста в середине движения без потери мира. Оптимизировать CPU независимо от GPU и повторить сравнение.

## Вне рамок
Обещание одинаковой скорости CPU/GPU и замена 3D раскрашенной плоской картой.

## Шаги
1. Подключить CPU-математику и векторный вывод к общим ресурсам.
2. Обеспечить программный путь всех функций, включая глубину 3D.
3. Провести принудительные CPU-тесты и локальную оптимизацию.

## Обязательные условия выполнения
Полностью прочитать общий контракт и исходное ТЗ. Каждый этап реализации сопровождается собственными тестами и циклом замер → одна оптимизация → повторный замер → сохранить улучшение или откатить, как подробно задано общим контрактом. Общий цикл навыка выполняет только завершающая задача группы. Проверять текущий код после зависимостей, а не копировать исходное состояние.
