# Контрастные цвета соседних сущностей

## Что и зачем
Выбирать максимально различимые локальные цвета из полного RGB-диапазона и менять уже назначенный цвет только при точном совпадении цвета новых соседей.

## Готово, когда
Острова одной сущности имеют один цвет; неизвестные/невидимые сущности не запускают подбор; фиксированные легенды не меняются. При изменении цвета геометрия и её загрузка не затрагиваются.

## Точный алгоритм участка
Собрать объединение соседей всех компонент сущности по мировому индексу: ранее окрашенные в этом визуальном контексте соседи, фиксированные цвета реально прилегающих рек и моря. Не назначать цвета неизвестным соседям. RGB-кандидаты — все 24-битные значения кроме 000000 и ffffff; сравнение в OKLab, цель лексикографическая: максимизировать минимальную дистанцию до соседей, затем сумму дистанций. Случайный выбор только между равными итогами, отдельный визуальный генератор не расходует RNG игры.
CPU-решатель использует поиск RGB-октодеревом с очередью верхних оценок, интервальными границами преобразования в OKLab и отсечением заведомо худших ветвей; не подменять весь диапазон фиксированной палитрой. Проверить оценку независимым полным перебором малых кубов и полным 24-битным эталоном вне UI; численный допуск сравнения 1e-6 OKLab. GPU-вариант пакетно вычисляет ту же целевую функцию и редукцию; решение имеет тот же результат в допуске. При первом цвете без соседей равномерный случайный допустимый RGB.
Равенство соседей определяется по сохранённому RGB, не по близости OKLab. При конфликте выбрать видимую сущность, чьи изменения вызвали соседство, иначе видимую с большим стабильным ID; остальные существующие цвета сохраняются. Учитывать все её окрашенные соседства, заменить одну запись цвета и повторно проверить конфликт. Невидимую сущность лишь пометить для проверки при следующем показе; без зрителя решений нет.

## Проверки и пороги
Проверить острова, объединение/разделение, соседей за экраном, границу с морем/рекой и возникновение равных соседей. Подбор CPU p95≤100 мс для 8 соседей вне UI на S, GPU измеряется отдельно; партия первых 20 цветов p95≤300 мс, UI-срез≤2 мс. Изменение цвета: записей CPU=1, GPU=1, тесселяций/upload геометрии=0. Если цветовой поиск не укладывается, оптимизировать поиск/кэш соседств, не ослаблять критерий и не менять цвет позже без конфликта.

## Вне рамок
Перекрашивание ради красоты уже различных соседей и изменение фиксированных легенд.

## Шаги
1. Реализовать соседства, цветовой критерий и независимый проверочный решатель.
2. Добавить CPU/GPU-исполнение и обработку конфликта одной сущности.
3. Измерить и оптимизировать выбор без изменения результата и правил перекраски.
