# Подписи по видимым контурам

## Что и зачем
Сохранить полноценную адаптивную типографику и пересчитывать расположение только после движения/масштаба либо изменения соответствующей геометрии, а не каждый кадр.

## Готово, когда
Во время жеста надписи едут и масштабируются вместе с картой; затем соответствуют пересечению нужных компонент с видимостью. Неизменные полностью видимые подписи восстанавливаются из кэша.

## Точный алгоритм участка
Ключ расположения содержит сущность/группу, версии компонент, текст/шрифт, масштаб и результат пересечения с видимостью, не глобальную worldVersion. При движении сохранять прежнюю векторную надпись и применять ту же матрицу; отменять только устаревшие задания надписей. После окончания вычислить точное пересечение геометрии/группы с просмотром, размещать по действующему ТЗ подписей: поворот/изгиб, максимальный подходящий шрифт и межбуквенный интервал, общая подпись фрагментов при допустимом переходе через воду/ничейную/чужую землю, иначе отдельные подписи. Не заменять алгоритм горизонтальным центроидом.
Кэшировать полностью видимую группу до изменения её геометрии/текста/масштабного класса; при повторном появлении сначала использовать её прошлое расположение. Для обрезанной группы кэшировать по фактическому пересечению, ограничивать LRU. Надписи городов/географии следуют действующей видимости значков, стран — режимам стран/городов, культур/религий/рас — своим слоям. Поиск положения/кривых вне UI; публикация одного согласованного результата без пустого промежутка. Изменение невидимого слоя не создаёт заданий.

## Проверки и пороги
Проверить изгиб/поворот, составные страны, береговую полосу, края экрана, реки вдоль русла и отсутствие пропадающих названий городов. Во время движения число запусков layout=0; повтор полностью видимой неизменной группы даёт cache hit. S: окончательное расположение p95≤150 мс после жеста, UI-публикация≤2 мс; ввод не тормозит. Оптимизировать по замерам без ухудшения геометрии текста.

## Вне рамок
Отмена прежнего ТЗ подписей и отдельные мобильные шрифтовые реализации.

## Шаги
1. Подключить версионированный кэш и матричное движение старых надписей.
2. Перенести действующий геометрический layout во внешний исполнитель.
3. Проверить полный набор подписей и задержку после жеста.

## Обязательные условия выполнения
Полностью прочитать общий контракт и исходное ТЗ. Каждый этап реализации сопровождается собственными тестами и циклом замер → одна оптимизация → повторный замер → сохранить улучшение или откатить, как подробно задано общим контрактом. Общий цикл навыка выполняет только завершающая задача группы. Проверять текущий код после зависимостей, а не копировать исходное состояние.
