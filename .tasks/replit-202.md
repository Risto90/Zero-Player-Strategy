# Тестовая APK и журналы

## Что и зачем
Создать не разовую APK, а повторяемый скрипт сборки с выбором профиля. Команда тестового профиля должна собирать APK из последнего актуального состояния кода и автоматически включать текущий набор тестов и тестовое меню. Рабочий runtime остаётся release-вариантом без Expo/Metro development mode, root-доступа и подключения телефона к компьютеру. Android SDK устанавливается только при выполнении задачи.

## Готово, когда
- Одна команда с обязательным профилем собирает нужный тип APK; профиль test выбирает актуальную ревизию рабочего кода, а не сохранённый вручную снимок или устаревшую сборочную копию.
- Скрипт при каждом тестовом запуске определяет текущий тестовый набор из проекта, проверяет актуальность списка тестов в мобильном меню, включает подходящие для устройства проверки и не требует вручную обновлять копию тестов. Неподдерживаемые на телефоне Node/браузерные тесты запускаются в среде и не изображаются пройденными на устройстве.
- Android SDK, совместимый JDK и инструменты сборки устанавливаются и настраиваются во время задачи; версии и процедура повторного запуска документированы. APK воспроизводимо устанавливается и работает без dev server, имеет отдельную тестовую идентичность и не требует root.
- В главном меню имеется тестовый раздел с прогрессом и результатом каждой запускаемой на устройстве проверки. Сейчас такого отдельного меню в главном экране нет; добавить его и связать с актуальным каталогом тестов.
- Первый этап: в среде проходят typecheck, полный применимый pnpm test, проверка скрипта на актуальность тестового набора, Expo/Gradle сборка, установка и автономный smoke test без Metro.
- Второй этап: пользователь запускает встроенные тесты и игровой smoke test на устройстве. Приложение сохраняет подробный отдельный журнал с временными метками, экраном/этапом, JS/Expo console, необработанными исключениями, отклонёнными Promise, стеками и результатами тестов; файл можно экспортировать через системное «Поделиться» без adb, root и development mode.
- Журнал ограничен по размеру и ротации, не скрывает ошибки, не мешает запуску при сбое записи и не сохраняет секреты или ненужные данные. Отличия JS-журнала от native crash до запуска JS документированы; нативные ошибки фиксируются лишь там, где это доступно без root.
- Пользователь получает APK и русскую краткую инструкцию; этап проверки завершается после получения и анализа экспортированного пользователем журнала.

## Вне рамок
Профиль production APK из опубликованной ревизии, Google Play, сторонняя отправка логов, чтение полного системного logcat без root, изменение игровых правил.

## Шаги
1. Установить Android SDK/JDK и подготовить воспроизводимую Expo/Gradle-сборку без dev server.
2. Реализовать единый скрипт сборки с явным выбором профиля и режим тестовой сборки из актуальной рабочей ревизии.
3. Синхронизировать тестовое меню на главном экране с текущими тестами проекта и проверять в сборочном скрипте, что список не устарел.
4. Добавить подробный локальный журнал, ротацию и экспорт; прогнать автоматические проверки среды и тестовую APK.
5. Передать APK пользователю, дождаться проверки и файла журнала, разобрать результаты и устранить обнаруженные ошибки.
