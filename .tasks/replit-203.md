# Продакшен APK опубликованной версии

## Что и зачем
Добавить production-профиль в тот же повторно используемый скрипт сборки APK. Команда production должна каждый раз определять последнюю фактически опубликованную ревизию приложения и собирать именно её, а не текущую рабочую копию или снимок, сохранённый при предыдущем запуске.

## Готово, когда
- Скрипт имеет явные режимы test и production. Запуск production автоматически разрешает последнюю опубликованную ревизию по проверяемому идентификатору/метаданным публикации, получает соответствующие исходники и ресурсы, фиксирует их ревизию и собирает APK; выбор версии вручную по умолчанию не нужен.
- Если среда публикации не предоставляет соответствия опубликованной версии конкретным исходникам, скрипт обнаруживает это и прекращает выпуск с понятной ошибкой, а не подменяет публикацию HEAD текущей ветки. Совпадение web-публикации с нативным APK подтверждается по исходной ревизии и конфигурации; несовпадение обозначается явно.
- APK является автономной release-сборкой, не зависит от Expo Go, Metro или dev server, не содержит тестового меню, тестовой инструментации и отладочных разрешений.
- В production включено только логирование ошибок и критических сбоев; подробные тестовые трассы туда не попадают.
- Проверены package ID, версия, подпись и обновление. Ключ подписи передаётся безопасно, не хранится в коде, репозитории или логах; если доступен только неподписанный installable-вариант, ограничения будущего обновления явно указаны.
- Одна команда production собирает APK в определённое место с метаданными опубликованной ревизии. Проверены установка, автономный запуск, базовый игровой сценарий и отсутствие тестовых экранов/адресов.
- Результат передан отдельно от тестовой сборки вместе с точной исходной опубликованной ревизией.

## Вне рамок
Публикация в магазине приложений, распространение через сторонний магазин, хранение ключа подписи в проекте, автоматический выбор текущей рабочей ветки вместо опубликованной версии.

## Шаги
1. Определить доступный источник метаданных последней опубликованной ревизии и критерий подтверждения соответствия кода публикации.
2. Добавить в общий скрипт production-профиль, который получает точную опубликованную ревизию, изолирует исходники и собирает только release-вариант.
3. Настроить подпись, идентичность приложения и логирование только ошибок; не включать тестовую инфраструктуру.
4. Проверить разрешение ревизии, сборку, установку и автономный игровой сценарий; передать APK и идентификатор источника.
