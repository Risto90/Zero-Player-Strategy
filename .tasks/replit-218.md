# WebGL и сохраняемые графические буферы

## Что и зачем
Заменить SVG-плитки одним управляемым контурным WebGL-исполнителем с повторным использованием готовой геометрии.

## Готово, когда
Карта использует буферы контуров, матрицу камеры и общую таблицу цветов сущностей; перемещение/масштаб не пересобирают и не перезагружают неизменную геометрию.

## Точный алгоритм участка
Создать один графический контекст и ресурсы программы, вершин, индексов, материала/цвета и камеры. WebGL2 использовать при наличии, совместимый аппаратный путь — по возможностям; отсутствие нужной возможности передаётся общему диспетчеру без второй реализации игровых правил. Геометрия ссылается на entityId/индекс материала; смена цвета обновляет только один элемент общей таблицы, не вершины каждой компоненты.
Вывод берёт готовые дескрипторы видимых компонент и отправляет команды для их целой геометрии с ограничением экранного framebuffer. Загрузка буфера может происходить без команды рисования; сохранённый буфер невидимой компоненты не означает её покраску на холсте. Локальную разность переносить через обновление затронутых диапазонов, не полную загрузку слоя. Отсутствие изменений и движения не требует постоянного цикла рисования. Потеря контекста сохраняет CPU-источник, инвалидирует только графические дескрипторы и восстанавливает по версиям.

## Проверки и пороги
На S выполнить 100 панорамирований/масштабирований: подготовок и загрузок геометрии=0 для резидентных неизменных компонент. Цвет: 1 запись материала, 0 загрузок вершин; скрытый холст: 0 draw-команд. Выполнить тест контекст потерян→восстановлен и сравнение изображения/геометрии с эталоном. Применяются GPU/UI-бюджеты общего контракта; отдельно CPU отправки и GPU-время, без gl.finish/readPixels в рабочем цикле. Оптимизировать после исходного замера.

## Вне рамок
Текстурный снимок карты, кэш плиток, мобильный комплект экранов и полное отключение деталей ради FPS.

## Шаги
1. Подключить единственный WebGL-исполнитель к готовой геометрии и общей таблице цветов.
2. Добавить локальные загрузки, повторный вывод и восстановление контекста.
3. Проверить команды и аппаратные бюджеты без подмены программным GPU.

## Обязательные условия выполнения
Полностью прочитать общий контракт и исходное ТЗ. Каждый этап реализации сопровождается собственными тестами и циклом замер → одна оптимизация → повторный замер → сохранить улучшение или откатить, как подробно задано общим контрактом. Общий цикл навыка выполняет только завершающая задача группы. Проверять текущий код после зависимостей, а не копировать исходное состояние.
