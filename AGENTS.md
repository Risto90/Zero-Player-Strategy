# Задачи Replit и GitHub

Правила этой страницы относятся ко всем агентам проекта, создающим, изменяющим
или завершающим задачи. Полная схема: `docs/github-tasks.md`.

## Создание и изменение

После успешного создания или изменения задачи в Replit, включая черновик,
записать полное актуальное описание задачи в
`.local/tasks/github-outbox/НОМЕР.json`. Это обязательная часть сохранения
плана, а не отдельная предлагаемая пользователю задача.

Формат: `sourceTask` — положительный числовой номер из `taskRef`;
`title`, `description`, `dependsOn`, `updatedAt` — точные значения из задачи
Replit; `resources` — полные тексты дополнительных обязательных планов,
на которые ссылается описание, в виде `{ "path": ".local/tasks/...", "content": "..." }`.
Не копировать личный профиль, ключи, логи или посторонние документы.
Не формировать задачи по одному факту существования Markdown-файла.

Запись делать целиком штатным инструментом записи файла. В режиме Plan
писать только разрешённые файлы описаний задач под `.local/tasks/`,
не запускать Git и не менять окружение: отправку выполняет уже настроенный
отдельный процесс «Синхронизация задач GitHub». Не утверждать, что Issue
опубликован, пока его существование не подтверждено.

В Build при отсутствии процесса допустим однократный запуск
`node scripts/github-tasks/publish.mjs`. Очередь нельзя удалять при ошибке.
Обнаруженный `index.lock` сначала исследовать; не удалять вслепую.

## Завершение

После реализации и успешных проверок включить в сообщение завершающего
коммита отдельную строку `Replit-Task-Completed: НОМЕР`. Если завершение
выполняется через `markTaskComplete`, передать эту строку в `commit_message`.
Задачу нельзя объявлять завершённой только ради закрытия GitHub Issue.

После попадания коммита в `main` GitHub Actions закрывает связанный Issue.
До этого момента задача на GitHub остаётся открытой. Не использовать эту
отметку для черновиков, частичной работы, отмены или архивирования.
