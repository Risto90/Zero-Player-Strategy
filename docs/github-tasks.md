# Синхронизация задач Replit и GitHub

Новые задачи в этом проекте создаёт агент в режиме Plan. После создания или
редактирования задачи он записывает её полное актуальное описание в исходящую
очередь `.local/tasks/github-outbox/НОМЕР.json`. Это файл описания задачи, а не
изменение приложения. Сам агент в Plan не делает Git-коммиты и не меняет окружение.

Отдельный процесс `node scripts/github-tasks/publish.mjs --watch` раз в 15 секунд
передаёт очередь в `.github/replit-tasks/` основной ветки GitHub. Он использует
отдельный временный индекс Git, не меняет текущую ветку, рабочее дерево и обычный
индекс, не захватывает код приложения. Принудительной перезаписи ветки нет.
При конфликте отправка строится заново поверх свежего `main`; при сетевой ошибке
очередь сохраняется до следующей попытки. При наличии `index.lock` публикация
останавливается с явной ошибкой, блокировка автоматически не удаляется.

Когда среда Replit выключена, процесс не работает. Очередь сохраняется в проекте
и передаётся после запуска процесса. В изолированном окружении агента задачи
тоже могут быть опубликованы командой без `--watch`, но только в Build.

## Файл задачи

```json
{
  "sourceTask": 194,
  "title": "Алгебра множеств и населения",
  "description": "Полное описание из результата создания или чтения задачи",
  "dependsOn": ["#193"],
  "updatedAt": "2026-10-27T19:13:23.250Z",
  "resources": []
}
```

Номер, описание, зависимости и время изменения берутся из самой задачи Replit.
Нельзя считать каждый случайный Markdown-файл из `.local/tasks/` новой задачей.
Черновики также экспортируются; отмена и архивирование не означают выполнение.
Файл заменяется целиком; во время записи нельзя оставлять частичный JSON.
Если план ссылается на дополнительные обязательные документы из `.local/tasks/`,
их точные тексты добавляются в `resources` как объекты `{ "path": "...", "content": "..." }`.
Секреты, личный профиль и посторонние документы не экспортируются.

GitHub Actions создаёт Issue по постоянному номеру Replit, обновляет управляемый
блок описания и название, сохраняет комментарии и пользовательский текст за
границами блока. Зависимости превращаются в ссылки, когда соответствующие Issues
появятся. Повторная отправка не создаёт дубликат. Предыдущая тестовая задача №194
подхватывается по прежней метке, а не создаётся заново.

## Завершение

Завершающий коммит должен содержать отдельную строку:

```text
Replit-Task-Completed: 194
```

Можно указывать несколько задач, по одной строке на каждую. Добавлять отметку
разрешено только после реализации и проверок. При использовании `markTaskComplete`
эта строка включается в `commit_message`, чтобы попасть в итоговый коммит.
Отметки в ветке разработки не закрывают Issues: коммит должен попасть в `main`.
Обычные упоминания номера, частичные исправления, очередь или отмена задачи
не закрывают Issue. Уже закрытые Issues повторно не открываются.

Actions проверяет достижимую из `main` историю, поэтому повторный запуск
восстанавливает пропущенное закрытие, даже если Issue появился после коммита.
Есть ежечасная повторная сверка при временных сбоях GitHub.

## Проверки

`node --test scripts/github-tasks/*.test.mjs`

Проверки не закрывают реальные игровые задачи: используют локальный временный
репозиторий и подставной API. Рабочий статус процесса виден в отдельном процессе
«Синхронизация задач GitHub», результат публикации Issues — в GitHub Actions.
